GET  /impressora/config        config da impressora (decisão 15) — boot passo 3
GET  /impressora/jobs          poll: jobs + payload base64 + config_version (decisão 13)
POST /impressora/jobs/:id/ack  marca printed (decisão 9) · responde {pending}
POST /impressora/printers      report do spooler (decisão 17) — boot passo 2, snapshot substitutivo
POST /impressora/logs          logs do debug_mode (decisão 18) · TTL 3 dias · teto 300 linhas

Ordem do boot do agente (decisão 17): token do arquivo → POST /impressora/printers (passo 2) → só então GET /config (passo 3) → loop poll→ack (passo 4). A superfície do owner (GET /owner/impressao lote do modo browser e GET /owner/impressao/status ticker de 30s) anda na sessão do dono — não aceita o token do device, fora do escopo deste tester.

Payload do POST /impressora/printers — report do spooler (decisão 17)

Snapshot substitutivo das impressoras instaladas (EnumPrinters): array com no máximo 50 entradas; cada entrada é um objeto de chaves livres (≤ 20 chaves de ≤ 40 chars, valores stringificados de ≤ 500 chars) e só sobrevive com name. Contrato cravado no épico S5: Porta = porta TCP numérica como string ("9100"), PortaNome = nome da porta no OS quando existir (IP_192.168.0.50, USB001), Host = IP/hostname da porta TCP/IP; todos os valores são strings (fonte: EnumPorts no Windows, URI socket:// do lpstat -v no Linux/macOS). O agente real filtra impressoras de arquivo/PDF/XPS antes do teto de 50. Edite à vontade para testar a saneação — o demo aplica os mesmos tetos do Rails. O report é consulta/sugestão e nunca vira config.

Payload do POST /impressora/logs — rodada de debug (decisão 18)

Com debug_mode ligado na config, cada rodada de execução do agente vira um POST com {"entries": [...]} — um POST = uma linha em printer_debug_logs. Saneação: máx. 200 entries de ≤ 2000 chars, em branco é descartado (POST vazio não cria linha morta — stored: 0). Vida útil de 3 dias: purga preguiçosa a cada POST + job diário; consulta no card Comandas do painel admin.

Como cadastrar o device de um negócio (e pegar o token)

O token pertence a um print_device do negócio (mesmo padrão do entregador — ADR-0001). Cadastre no Rails e cole o token aqui:

cd ~/mv/projects/localissimo

bin/rails runner '
  negocio = Business.order(:id).first   # ou find_by!(name: "Nome do negócio")

  device = PrintDevice.create!(business: negocio, name: "Tester HTML")
  Printer.find_or_create_by!(business: negocio) do |p|
    p.assign_attributes(name: "Cozinha – Tomate MDK-080",
                        host: "192.168.0.50", port: 9100)
  end
  puts device.access_token
'

No modo Demo não precisa de token (qualquer um vale). Nos servidores reais, os endpoints do S4 vivem na branch feat/comandas-termicas (S0–S4 feitos, sem merge na main) e o CORS para esta página já vem neles (middleware PrintAgentCors, liberado só em /impressora). No modo agent o token nasce no card do owner — "Conectar agente no Windows" cria/reusa o device "Agente no balcão" e mostra o token com copiar.
